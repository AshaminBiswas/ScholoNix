# UI/UX Design Skill

## Workflow
1. Identify the primary persona, task frequency, context of use, device, and permission level.
2. Map the task flow before designing screens; reduce steps for frequent tasks such as attendance and fee collection.
3. Establish information hierarchy, navigation, terminology, and page-level actions.
4. Design responsive states for mobile, tablet, and desktop.
5. Include empty, loading, error, success, offline/slow-network, and permission states.
6. Validate flows against real school workflows and avoid assumptions about staff technical skill.

## School SaaS principles
- Role-specific dashboards; do not show irrelevant metrics or actions.
- Bulk actions must preview affected records and require confirmation for destructive changes.
- Search, filters, saved views, pagination, and clear table density controls for large datasets.
- Financial actions must show amount, student/account, due date, payment method, and receipt outcome clearly.
- Use plain language and consistent academic terminology.

## Deliverables
User flows, low/high-fidelity screen specification, component inventory, responsive behavior, and accessibility notes.
